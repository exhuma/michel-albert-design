Design system

Calm, precise, plain.

The visual identity for my site, blog, self-hosted tools, READMEs and talks. Dark is the main theme. One teal accent sits on warm brown neutrals, set in Source Sans 3 with 4px corners and flat surfaces.

See the componentsRead the palette →

Colour

Text sits on surface-100, surface-200 or surface-300. The accent is the only hue that is not a state, apart from the six diagram colours, which only tell categories apart in diagrams and stay distinct for colour-blind readers. Switch the theme to see both palettes.

Type

Source Sans 3 for all text, Source Code Pro for code, paths and figures. Headings use weight 600 and nothing heavier.

Shape and spacing

Surfaces are flat and separated by 1px hairlines. Boxes use a 4px radius, tags 2px, tables none.

One exception: a reading sheet on a wide screen is raised. It casts a soft even halo, 0 0 40px 4px in shadow, and the contour lines around it stay crisp beside it and fade toward the screen edges. Nothing else casts a shadow.

Backdrops

Covers, section slides and the space around a docs reading sheet carry a seeded backdrop. There are nine styles. Each project picks one, and its name is the seed, so the picture stays the same on every build and differs from every other project.

BackdropFeelUse for

Choosing one

  1. Pick by the subject's main metaphor, using the table. When nothing clearly fits, use Contours.
  2. One backdrop per project. A deck, its course handouts and its docs share it; never mix styles within one.
  3. Seed with the project or deck name, for example Overview of HTTP or t61codec.
  4. Content slides and reading sheets stay plain. Backdrops only sit behind titles, section dividers and wide-screen margins.
  5. Backdrops use the background, the hairline colour and lightness steps between them. Never add a hue or raise their contrast.

Source: backdrops.js, published with this page. Call MaBackdrops.drawBackdrop(ctx, "circuit", "Overview of HTTP", "dark") on any 16:9 canvas. Palettes: dark for talks and dark pages, sand for courses, paper for light pages.

Slides

Slides leave the audience free to listen. Everything on screen either proves the point I am making or tells people where they are. Speaker notes never appear on the audience screen.

There are two deck types. Talks are heard once. Courses run over days and people look things up in them afterwards, so they carry more text and more orientation.

iWhy

Text that repeats what I say lowers recall (Mayer, redundancy principle), so notes stay off screen and talks avoid bullets. Cueing where to look beats making everything equally visible (signalling), hence the focus rule. Revealing complex material in steps helps (segmenting). Sentence headlines with visual evidence beat topic titles with bullets for technical audiences (Alley, assertion-evidence).

Imagery

No illustration and no icon set. Photographs and screenshots get a 1px hairline and the 4px radius, with a plain caption underneath.

Voice: short sentences, sentence case, no emoji, no exclamation marks. Name things by what they are.
